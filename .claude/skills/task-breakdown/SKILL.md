# Task Breakdown

## Phase 1: แตก task
1. อ่านโค้ดที่เกี่ยวข้องก่อน ห้ามเดา
2. เขียน `TASKS.md` ที่ root ของโปรเจกต์:

   ```
   # <ชื่องาน>

   - [ ] 1. <งานย่อย>
     - test: <วิธีพิสูจน์ว่าเสร็จ เช่น คำสั่งที่ต้องรันหรือผลที่ต้องเห็น>
   - [ ] 2. ...
   ```

   กฎการแตก task:
   - เรียงตาม dependency ข้อที่ต้องทำก่อนอยู่บน
   - 1 ข้อ = 1 อย่างที่ test ได้ ถ้าใหญ่เกินให้แตกต่อ
   - ทุกข้อต้องมีบรรทัด `test:` ถ้าไม่มีวิธี test แปลว่ายังไม่ใช่ task
3. แสดง list ให้ user ดู แล้ว**รอ "ตกลง"**

## Phase 2: ทำทีละข้อ
สำหรับแต่ละ task ตามลำดับ:
1. dev: แก้โค้ดของข้อนี้เท่านั้น
2. test: รันตาม `test:` ของข้อนั้น
3. ผ่าน: เปลี่ยน `[ ]` เป็น `[x]` แล้วต่อท้ายผล เช่น `✓ <คำสั่ง> pass`
4. ไม่ผ่าน: ห้ามติ๊ก ให้หยุดแล้วรายงานตาม skill `problem-report` แล้วรอ user
5. รายงานสั้นๆ 1 บรรทัด แล้วไปข้อถัดไป

## Phase 3: จบงาน
- ทุกข้อเป็น `[x]`: สรุปสั้นๆ ว่าทำอะไรไปและ test อะไรไป แล้วเรียก skill `qa-tester` กับงานทั้งหมดใน list นี้
- `qa-tester` เจอ ❌ และ user "ตกลง" วิธีแก้แล้ว: เพิ่มเป็น task ใหม่ท้าย list แล้วทำต่อด้วย Phase 2
- `qa-tester` ไม่มี ❌ แล้ว: เรียก skill `review-fix` ถ้ามี ⚠ manual ให้แจ้ง user ในสรุปด้วย
- `review-fix` ได้ ✅: จบงาน
- ถ้าระหว่างทางเจองานใหม่ ให้เพิ่มเป็นข้อใหม่ท้าย list ห้ามทำแอบ
- ถ้าเปิด session ใหม่แล้วมี `TASKS.md` อยู่แล้ว ให้ทำต่อจากข้อแรกที่ยังเป็น `[ ]`
