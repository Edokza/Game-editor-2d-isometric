# Review-Fix Loop

## รอบแรก
1. รีวิวด้วย skill `pr-review`
2. แสดงผลรีวิวแล้ว**รอ "ตกลง" ครั้งเดียว** เมื่อ user ตกลงแล้ว รอบต่อๆ ไปให้วนเองไม่ต้องถามซ้ำ

## วนรอบ (สูงสุด 5 รอบ)
1. **แก้**: แก้เฉพาะ 🔴 และ 🟡 ไม่ต้องแก้ 🔵 nit
   - แก้ที่ root cause ห้ามเพิ่ม scope และห้าม refactor ส่วนที่ไม่เกี่ยว
   - เมื่อแก้แล้ว ให้รัน test หรือ build ของโปรเจกต์ (ถ้ามี) ต้องผ่านก่อนรีวิวรอบถัดไป
2. **รีวิว**: ให้ subagent ที่ไม่เห็น context เดิมเป็นคนรีวิวตาม `pr-review`
   เหตุผล: ถ้าคนแก้รีวิวงานตัวเอง มักจะเห็นว่าตัวเองถูก
3. รายงาน 1 บรรทัดต่อรอบ: `รอบ N: 🔴 x 🟡 y → แก้ z ข้อ`

## เงื่อนไขหยุด
- ✅ verdict merge ได้: จบ แล้วสรุปว่าแต่ละรอบแก้อะไรไป
- ครบ 5 รอบแล้วยังไม่ผ่าน: หยุด แล้วรายงานตาม `problem-report`
- จุดเดิมที่ระดับเดียวกันยังอยู่ 2 รอบติด แปลว่าแก้ไม่ถูกจุด: หยุด แล้วรายงานตาม `problem-report`
- รอบใหม่มี 🔴 เพิ่มขึ้น แปลว่าการแก้สร้าง bug ใหม่: หยุด แล้วรายงานตาม `problem-report`
- ห้ามโพสต์ comment ลง PR และห้าม push เอง ต้องถาม user ก่อน
